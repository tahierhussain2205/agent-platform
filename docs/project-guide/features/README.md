# Features

What the platform does, as people in Slack and admins in the console experience it.

| Feature | In short |
|---|---|
| [1. The demo, step by step](01-demo-walkthrough.md) | From a bug report in a Slack channel to Jira tickets, a plan and a pull request, with the tickets following along |
| [2. The assistant in Slack](02-slack-assistant.md) | Mentions and DMs, sourced answers and summaries, private delivery, the status message, buttons, the App Home, access requests |
| [3. Jira tickets from chat](03-jira-tickets.md) | Problems discussed in a channel become tickets, checked for duplicates, with owners backed by evidence |
| [4. Investigations and plans](04-investigations-and-plans.md) | Parallel investigation of logs, code and recent changes, and a plan whose claims are checked |
| [5. Code changes and pull requests](05-code-changes-and-pull-requests.md) | The plan carried out in a sandbox, tested, reviewed and pushed as a pull request; review comments addressed in the thread |
| [6. Scheduled reports](06-scheduled-reports.md) | Recurring channel summaries and Jira progress reports, with numbers computed by code |
| [7. Autonomy and approvals](07-autonomy-and-approvals.md) | Ask or Auto, action tiers, approvals in Slack, shadow mode |
| [8. Roles](08-roles.md) | Profiles that shape answers, a live preview, limits that narrow what the agent does, approvals routed to a role |
| [9. The admin console](09-admin-console.md) | Every console page, including the Tasks timeline |

## Who uses what

| Person | Uses | For |
|---|---|---|
| Anyone in the org | Slack | Asking questions, summaries, tickets, investigations, changes; approving their own requests; their settings in the App Home |
| Admins | The console | Connecting Slack and tools, choosing channels, members and roles, limits and autonomy, schedules, usage and audit |
| Members (not admins) | The console, read only | Seeing the setup, their own tasks, linking their own Jira and GitHub accounts |
| Approvers | Slack buttons | Deciding approval requests routed to them (a role such as Tech Lead, or any admin) |
